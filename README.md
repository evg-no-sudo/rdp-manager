# Linux RDP Manager

Нативный RDP-клиент для Linux на Rust, GTK4 и libadwaita.
Основная среда разработки: Linux Mint 22.3 Cinnamon/X11.

## Требования совместимости

Обязательные целевые окружения: Cinnamon, GNOME и KDE Plasma.
Приложение должно работать с X11 и нативным Wayland; запуск через XWayland
не заменяет проверку Wayland. Поддержка пока не подтверждена во всей матрице.

- Не принуждать `GDK_BACKEND=x11` и не встраивать окно внешнего xfreerdp.
- Отрисовку RDP и обработку клавиатуры/мыши строить через GTK/GDK;
  не зависеть от Xlib, XID, глобального захвата ввода и X11 keycode.
- Проверять раскладки, модификаторы, фокус, сочетания клавиш, масштабирование
  HiDPI и перенос окон между мониторами под обоими оконными протоколами.
- Двусторонний буфер обмена текста и файлов проверять отдельно под Wayland
  и X11; доступ к локальному clipboard выполнять через GDK.
- Для выбора файлов использовать системные диалоги GTK; при упаковке
  учитывать desktop portals и соответствующий backend окружения.
- Хранилище паролей подключать через Secret Service D-Bus API, без привязки
  к GNOME Keyring. В KDE проверять наличие Secret Service-провайдера;
  недоступное или заблокированное хранилище обрабатывать явно, без сохранения
  паролей открытым текстом.

Матрица ручных проверок:

| Окружение | X11 | Нативный Wayland |
| --- | --- | --- |
| Cinnamon | Минимальный UI проверен пользователем | Требует проверки на версии с доступной Wayland-сессией |
| GNOME | Требует проверки | Требует проверки |
| KDE Plasma | Требует проверки на версии с доступной X11-сессией | Требует проверки |

В каждой доступной сессии проверять окна, вкладки, диалоги и профили;
после интеграции FreeRDP — подключение, ввод, clipboard, файлы и Secret Service.

## Текущий этап

Минимальный интерфейс: создание и закрытие вкладок, скрываемая панель профилей,
перенос выбранной вкладки в отдельное окно кнопкой «В отдельное окно».
Профили сохраняются в SQLite: название, сервер, порт, пользователь и домен.
Кнопка «Создать профиль» открывает форму; щелчок по профилю — редактирование.
Удаление требует подтверждения. Списки обновляются во всех окнах приложения.
Проверяются обязательные поля и диапазон порта 1–65535.

База: `${XDG_DATA_HOME:-$HOME/.local/share}/rdp-manager/profiles.sqlite3`.
Используются версионирование схемы и транзакционная миграция.
Пароли сохраняются только локально через Linux Secret Service (`libsecret`).
В форме профиля доступны новый пароль, проверка наличия сохранённого пароля
и отметка удаления пароля. Пустое поле оставляет пароль без изменений.
При удалении профиля сначала удаляется локальный пароль. Если Secret Service
недоступен или разблокировка отменена, показывается ошибка без записи секрета
в SQLite/файл. Сохранение параметров и пароля — отдельные операции: если пароль
не сохранён, параметры остаются в базе, форма позволяет повторить попытку.

У профилей появились стабильные UUID; существующая база автоматически
обновляется до схемы 2 без удаления профилей. Пароль привязан к UUID,
а не к названию профиля. Проверки описаны в [docs/TESTING.md](docs/TESTING.md).
RDP-сессии, история и WebDAV-синхронизация пока не реализованы.

Импорт Remmina: кнопка «Импорт Remmina…», выбор нескольких `.remmina`-файлов,
предварительный просмотр и отметки нужных профилей. Переносятся только
название, сервер, порт, пользователь и домен. Пароли, команды, шлюзы,
SSH-туннели и остальные параметры не переносятся; это указано перед импортом.
IPv4, DNS, IPv6 и `[IPv6]:порт` поддерживаются. Другие протоколы и ошибочные
файлы показываются в списке с причиной пропуска. Одинаковые записи
(название, сервер без учёта ASCII-регистра, порт, пользователь, домен)
пропускаются; существующие профили не перезаписываются. Запись выбранного
набора выполняется одной транзакцией. Лимиты: 200 файлов, 1 МиБ на файл.
Чтение выполняется асинхронно через GIO, выбор файлов — GTK FileDialog.
Чтение всего каталога Remmina пока не реализовано.

Кнопка «Обмен через папку…» позволяет выбрать профили и сохранить их
в зашифрованный `.rdpm`-файл либо открыть такой файл с другого устройства.
Мастер-пароль при экспорте задаётся отдельно (минимум 12 символов) и подтверждается.
На принимающем ПК нужен тот же мастер-пароль. Пароли RDP в набор не включаются.
Перед применением доступны отметки нужных профилей; совпадения пропускаются,
для изменённых профилей можно выбрать копию либо явную замену локальной версии.
UUID при замене сохраняется, локальные пароли не изменяются.

Это первый этап — ручной перенос и резервная копия, без автоматической
синхронизации и переноса удалений. Каждый экспорт создаёт новый файл.
Подробности формата и ограничения — в [docs/TRANSFER.md](docs/TRANSFER.md).

## Сборка и запуск

Нужны Rust/Cargo, pkg-config, GTK4 >= 4.14 и libadwaita >= 1.5 с dev-пакетами, а также `libsqlite3-dev` и `libsecret-1-dev`.
Для сохранения паролей нужен запущенный Secret Service-провайдер в пользовательской D-Bus-сессии.

```bash
cargo build --locked
cargo run --locked
```

Проверка изменений:

```bash
cargo fmt --check
cargo clippy --locked -- -D warnings
cargo test --locked
```

Ручная проверка: создать несколько вкладок кнопкой «+», закрыть вкладку,
скрыть и показать профили, перенести вкладку в отдельное окно,
закрыть все вкладки и создать новую.
Создать профиль, перезапустить приложение и проверить сохранение полей;
изменить порт, проверить обновление в отдельном окне. Проверить отказ
при пустом сервере и порте 0/65536, отмену удаления и подтверждённое удаление. Закрытие последнего окна завершает приложение.

## План разработки

1. Минимальный интерфейс проверен пользователем на Cinnamon X11.
2. SQLite: профили и миграция реализованы; импорт выбранных Remmina-файлов с предварительным просмотром реализован; далее импорт каталога, история и перенос между устройствами.
3. Linux Secret Service реализован; проверен изолированным тестом с GNOME Keyring. GUI проверен пользователем на Cinnamon/X11; KDE ещё требует проверки.
4. Native FreeRDP 3: небольшой C ABI bridge, проверка сертификата, подключение,
   вывод framebuffer и ввод. GTK работает в главном потоке, FreeRDP — в рабочем.
5. Опциональное Kerberos SSO через пользовательский ticket cache; вступление ПК
   в домен не требуется, но нужны DNS/KDC, корректные SPN и действующий билет.
6. Двусторонний текстовый clipboard (CLIPRDR), затем файлы через CLIPRDR
   и/или перенаправление диска RDPDR с явным выбором разрешённых каталогов.
7. Корректное отключение сессий при закрытии вкладок, восстановление состояния.
8. Встроенная зашифрованная синхронизация: локальная папка, WebDAV/Nextcloud, затем SMB и SFTP; требования в [docs/SYNC.md](docs/SYNC.md).

FreeRDP/WinPR 3.32.2 — целевая версия следующего этапа. Сейчас приложение
не линкуется с FreeRDP и не запускает внешний xfreerdp.
