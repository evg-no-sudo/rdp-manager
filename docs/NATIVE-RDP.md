# Native FreeRDP frontend — первый этап

## Использование

Нажатие на название профиля открывает настройки. Кнопка ▶ сразу подключает
по сохранённым параметрам и локальному паролю Secret Service. Если пароль
отсутствует или хранилище недоступно, показывается только запрос пароля с
возможностью сохранить его на этом ПК. Промежуточной формы подключения нет.

Раскладка, качество и разрешение находятся в свёрнутых дополнительных
настройках профиля. По умолчанию RU, приоритет чёткости и автоматическое
разрешение. Фиксированные 1280×720, 1600×900, 1920×1080 доступны там же.
Параметры сеанса сохраняются локально в SQLite (schema 5); текущий формат
обмена профилями их пока не переносит. Пароли в SQLite не попадают.

Автоматическое разрешение задаётся по рабочей области вкладки с учётом
масштаба GTK. Изменения объединяются за 200 мс и отправляются через RDP
Display Control после получения возможностей сервера. При изменении окна,
боковой панели и переносе вкладки в отдельное окно запрашивается новый размер.
Границы: 200–8192, чётные размеры, до 16 мегапикселей и лимита сервера.
Если сервер не предоставляет Display Control, используется локальное
масштабирование картинки с сохранением пропорций. Отдельного переподключения
из-за изменения окна нет.

Захват клавиатуры запрошен по умолчанию при фокусе в рабочем столе.
Повторный щелчок по кнопке или правый Ctrl отключают его. Кнопка не забирает
фокус перед щелчком, поэтому focus-leave не переворачивает её состояние.
При потере фокуса/unrealize освобождается фактический системный захват;
выбор пользователя остаётся в кнопке и применяется при возвращении фокуса.
Wayland-композитор может ограничить системные сочетания.

В меню ⋮ у строки подключения доступно «Клонировать…»: создаётся черновик
с новым UID и именем копии, копируются поля и дополнительные настройки.
Доступный локальный пароль подставляется в форму; сохраняется для нового UID
только после «Сохранить». Закрытие черновика ничего не создаёт. Ошибка чтения
пароля показывается отдельно. Исходный профиль и его пароль не меняются.
Копии получают независимые записи настроек и Secret Service.

В меню «⋮» доступна история последних 100 подключений: начало, факт
установления связи, конец, результат. Пароли в историю не входят,
история не включается в наборы обмена. База обновляется до схемы 5,
существующие профили и доверенные ключи SFTP сохраняются.
Незавершённые записи после сбоя помечаются при следующем запуске.

## Архитектура

- `native/rdp_bridge.c` содержит небольшой C ABI над установленным FreeRDP.
  Сборка через pkg-config и cc. Нужен FreeRDP >= 3.25; проверена версия 3.32.2.
- Виртуальные каналы загружаются через instance.LoadChannels. PreConnect
  регистрирует только события: FreeRDP пересоздаёт channel manager после него.
  Загрузка addins в PreConnect приводит к потере каналов при пересоздании.
- Каждый сеанс владеет FreeRDP-контекстом в одном Rust-потоке. Соединение,
  обработка основного протокола и ввод выполняются в этом потоке. EGFX callbacks
  библиотеки синхронизируются с чтением framebuffer через locks. GTK не получает
  указатели на GDI и не вызывает FreeRDP input из главного потока.
- GTK получает копию последнего BGRX-кадра, нормализует альфу и создаёт
  GDK MemoryTexture. Обновления EndPaint объединяются до конца протокольного цикла.
  Завершённый серверный кадр предлагается GTK непосредственно на EndFrame,
  до следующего StartFrame, а не только в конце сетевого цикла. Если GTK занят,
  копирование пропускается,
  dirty-флаг сохраняется до следующей попытки, включая последнее обновление.
  Picture обновляет текстуру по GTK frame clock; отдельный 16-мс таймер
  обрабатывает статусы/сертификаты и не задаёт такт показа.
  Начальный и изменённый framebuffer обнуляются до использования.
- Размер framebuffer ограничен 8192 по каждой стороне и 16 мегапикселями
  в сумме. Проверяются stride и длины перед копированием через FFI.
- Ввод идёт через ограниченную очередь; движения мыши объединяются.
  При переполнении сеанс останавливается, а не теряет произвольный key-up.
- В режиме по умолчанию обычные клавиши передаются сканкодами, раскладку
  обрабатывает сервер. В меню параметров ввода есть альтернативный Unicode
  через GTK IMContext. Специальные клавиши и
  горячие сочетания — RDP-сканкодами. Backend-зависимый GTK keycode используется
  только как локальный идентификатор удерживаемой клавиши и для запроса
  логических символов через GDK, не преобразуется вычитанием X11-offset.
  При потере фокуса отпускаются удерживаемые клавиши и кнопки мыши.
  При штатной остановке worker также отправляет отпускание до разрыва связи.
- Единственный параллельный native вызов — запрос отмены: атомарный флаг,
  а при незавершённом подключении также установка abort event.
  Активный сеанс выходит из цикла с ожиданием не более 15 мс и освобождает ввод.
  Mutex защищает время жизни opaque-указателя от гонки отмены и освобождения.
  Вкладка/окно явно вызывают остановку; освобождение widget служит дополнительной
  страховкой. Во время ожидания решения по сертификату отмена тоже проверяется.

## Аутентификация и сертификаты

TLS и NLA разрешены, legacy RDP Security выключен. Проверка сертификата
не отключается: IgnoreCertificate/AutoAcceptCertificate выключены.
Для непроверенного сертификата показываются адрес, имя, субъект, издатель
и SHA256 fingerprint. По умолчанию — отказ. Можно явно разрешить только
текущий сеанс или отметить «Запомнить сертификат для этого сервера».
Второй вариант сохраняет исключение в собственном хранилище доверия FreeRDP
RdpManager/RdpManager1 с привязкой к имени/порту. Следующее соединение с тем же
сертификатом не требует вопроса. Изменённый сертификат отклоняется. Изменённый кешированный сертификат
отклоняется без кнопки обхода; его прежний/новый отпечатки показываются отдельно.
FreeRDP использует собственное пространство конфигурации RdpManager/RdpManager1.

Учётные данные передаются в память FreeRDP, не в аргументы внешнего процесса.
Временные Rust-буферы пароля очищаются; перед освобождением настроек очищается
их Password. Полного отсутствия копий в памяти сторонних библиотек это не
гарантирует. Дампы транспорта и дисковый bitmap cache выключены.
Нельзя трактовать «Подключено» как доказательство успешного входа в Windows:
при TLS без NLA сервер может показать собственный экран входа.
FreeRDP использует встроенное согласование SSPI; отдельные настройки
Kerberos SSO в интерфейсе будут добавлены следующим этапом.

## Ограничения этапа

Подключён канал EGFX/RDPGFX через штатный gdi_graphics_pipeline_init FreeRDP.
Серверы без EGFX продолжают использовать классический software GDI.
RemoteFX и NSCodec разрешены для согласования с сервером, вместо принудительного
отключения обоих сжатых режимов. Это графические кодеки, не RemoteFX vGPU.
H.264/AVC444 объявляются только при WITH_GFX_H264=ON в реально загруженной библиотеке.
Classic SurfaceFrameMarker/AltSecFrameMarker и EGFX StartFrame/EndFrame учитываются:
незавершённый серверный кадр не публикуется. EGFX framebuffer читается под mux
декодера; создание/закрытие pipeline и frame boundary защищены общим lock.
Само изображение пока проходит через CPU и MemoryTexture, без zero-copy и
dirty-region оптимизации. Поддержка аппаратного декодирования ещё не подтверждена;
наличие GTK/GPU-рендеринга не означает аппаратное декодирование RDP.
Пока используется локальный стандартный курсор, формы удалённого курсора
не отображаются. Автоматическое изменение разрешения зависит от поддержки Display Control сервером.
Clipboard, файлы, звук, устройства, RemoteApp, переподключение и сохранение
раскладки окон ещё не реализованы. Для полноценных IME/раскладок/горячих клавиш
и compositor-перехватываемых сочетаний нужна проверка в реальной сессии.

Протокол, NLA, кадр, ввод и отмена проверены синтетическим loopback-peer,
без захвата экрана пользователя. GUI и совместимость с настоящим Windows
нужно проверить вручную. Общая матрица Linux-окружений пока остаётся открытой.

API-ориентиры: [FreeRDP sample client](https://github.com/FreeRDP/FreeRDP/blob/3.32.2/client/Sample/tf_freerdp.c),
[FreeRDP public headers](https://github.com/FreeRDP/FreeRDP/blob/3.32.2/include/freerdp/freerdp.h).


## Клавиатура и захват сочетаний

По умолчанию выключен Unicode: для xrdp используйте нажатия клавиш и
переключайте EN/RU в удалённой системе. Локальная RU раскладка сопоставляется
с базовыми символами через GDK map_keycode, без предположений об X11 offset;
есть резервное сопоставление стандартной ЙЦУКЕН.
Поддержка произвольных нестандартных физических раскладок ещё требует работы.

«Захват клавиш» запрашивает GDK inhibit_system_shortcuts. Правый Ctrl
освобождает клавиатуру и отпускает удерживаемые клавиши. При потере фокуса,
закрытии или отключении захват также освобождается. Wayland-композитор/WM
может отклонить запрос или оставить собственную аварийную комбинацию.
Это не обещание перехвата всех системных клавиш на каждом окружении.
Режим Unicode остаётся в меню параметров ввода для совместимых серверов.

Диагностика сборки без открытия GUI или подключения к серверу:

    cargo run --locked -- --diagnostics

План оптимизации и аппаратного ускорения: [PERFORMANCE.md](PERFORMANCE.md).


## Диагностика реального графического режима

    RDP_MANAGER_TRACE_GRAPHICS=1 cargo run --locked

Раз в три секунды worker выводит строку [rdp-graphics]. Адрес, пользователь,
пароль, вводимый текст и изображение в неё не входят. mode=EGFX означает
подключённый графический канал; channel_loads — число успешных загрузок
каналов через callback LoadChannels; codec_id — ID реально полученной EGFX
SurfaceCommand (0 uncompressed, 9 progressive, 10 planar, 11 AVC420,
14 AVC444, 15 AVC444v2). До первой команды ID равен нулю, SolidFill его
не меняет. В classic classic_codec отражает последний BitmapUpdate или
SurfaceBits: bitmap, RemoteFX, NSCodec, raw-surface, other-surface.

paints — вызовы EndPaint с изменениями, frames — EndFrame/frame markers,
copies — принятые снимки framebuffer, copy_us — суммарное время callback
копирования (включая проверку занятого слота), size — разрешение. rfx/nsc
показывают флаги возможностей, а не доказательство использования кодека.
Счётчики накопительные за сеанс. Это не замер RTT/input latency и не
подтверждение работы аппаратного декодера.

[rdp-present] выводит фактический тип GTK renderer и частоту установки новых
текстур на видимой вкладке. Это не измерение физического обновления монитора.
На скрытой вкладке frame clock не вызывается и строка не выводится.


## Ввод и короткая задержка

Режим «Раскладка: сервер» не отправляет Unicode даже при отсутствии
результата GDK map_keycode: используются базовые EN/RU символы как резервное
сопоставление. Неизвестная клавиша не превращается неявно в текст. IM commit
и key-release фильтруются через IMContext только в явном Unicode-режиме.
Резервные символы Alt/Shift учитываются для ISO_Next_Group.
В меню ввода есть Alt+Shift, Ctrl+Shift и Win+Space: это нажатия на сервере,
они работают только если соответствующее переключение настроено там.

Очереди клавиш/мыши уведомляют WinPR manual-reset event. Worker сбрасывает
событие перед чтением очередей, а не после ожидания, чтобы не потерять
уведомление между чтением очереди и poll. Ввод не ждёт очередного 15-мс
таймаута. Событие и контекст освобождает owner; native mutex защищает wake
и cancel от гонки с освобождением. В диагностике input_wakes, scans и unicode
считают события; текст и коды конкретных клавиш не записываются.
hw_requested сообщает запрос H.264 GPU, не фактически выбранный декодер.

Отдельная сборка с H.264, настройки AMD/Intel/NVIDIA и тесты: [H264.md](H264.md).


## Начальная раскладка и кириллица

В диалоге подключения явно задаётся KeyboardLayout: US 0x409 или RU 0x419,
тип Enhanced PC (4), 12 функциональных клавиш. Выбор действует на этот сеанс.
По языку локальной системы предварительно выбирается RU или US; это не
определение текущей группы XKB. Для проверки русского ввода выберите RU явно.

В Unicode-режиме обычные кириллические keyvals U+0400–U+052F передаются
непосредственно как UTF-16 до IMContext. Это устраняет зависимость стандартного
кириллического ввода от того, выдаст ли локальный IM commit на Picture.
Остальные символы продолжают использовать IMContext; полноценные составные
IME и экзотические раскладки требуют отдельной проверки. В сканкодном режиме
по состоянию GDK отпускаются потерянные левые Alt, Ctrl, Shift, Super;
локальное переключение раскладки может перехватить key-up.

Кнопка «Отправить „Привет“» в меню ввода передаёт заданную тестовую строку
через Unicode независимо от выбранного режима. До нажатия откройте редактор
на удалённой машине. Она ничего не вставляет и не меняет автоматически.
Сетевой fixture проверяет полученные UTF-16 коды и KeyboardLayout=1049,
но не заменяет проверку отображения в Windows/xrdp.

## Чёткость и динамичное изображение

Текстовый буфер обмена передаётся через CLIPRDR в обе стороны как CF_UNICODETEXT.
GTK читает локальный буфер асинхронно; последняя локальная копия ограничена 1 МиБ.
Удалённые данные свыше 2 МиБ отклоняются. Форматы файлов пока не объявляются.
После подключения проверить копирование кириллицы в обе стороны в текстовом
редакторе Windows и xrdp. Loopback-тест проверяет обмен Unicode на уровне
обработчиков канала, но не системный буфер удалённого рабочего стола.

Перед подключением доступны «Авто: скорость и качество» и
«Приоритет чёткости (без H.264)». Авто разрешает серверу AVC444/AVC420 при
наличии декодера. Вариант чёткости исключает H.264/AVC и сохраняет EGFX
Progressive и classic fallback. Сервер может выбирать сжатие сам; это не
обещание lossless. На Linux такой режим может быть медленнее H.264/VA-API.
AVC420 использует цветовую субдискретизацию, которая особенно заметна на
цветном мелком тексте. Увеличение/уменьшение картинки в GTK также влияет
на чёткость. Качество кодирования и выбор AVC444 нельзя навязать серверу,
который этот вариант не поддерживает.

Режим «AVC444: скорость и чёткий текст» не объявляет возможности EGFX 8.1,
через которые FreeRDP предлагает AVC420. Он сохраняет EGFX 8 и 10+,
AVC444 и fallback без H.264. Нужна сборка FreeRDP с H.264 и поддержка AVC444
на сервере; иначе сервер может выбрать другой кодек. Проверять фактический
`codec_id`: 14/15 означает AVC444, 11 означает AVC420. Если сервер всё же
присылает AVC420 или не подключается, выбрать «Приоритет чёткости».
На Windows Server выбор AVC444 может зависеть от серверной политики
[Prioritize H.264/AVC 444 graphics mode](https://learn.microsoft.com/en-us/windows/client-management/mdm/policy-csp-admx-terminalserver).


Для проверки артефактов H.264 в дополнительных настройках профиля есть
«H.264 без GPU (совместимость)»: AVC остаётся разрешён, аппаратный запрос
выключен для этого сеанса. Если полосы остаются, это не доказывает ошибку GPU:
сервер мог выбрать другой кодек или применить потери при сжатии. Для сравнения
сохранять одинаковые разрешение/содержимое и записывать codec_id в обоих сеансах.
Без H.264 режим чёткости остаётся безопасным значением по умолчанию.


Режим «Точная передача (без потерь)» исключает EGFX, RemoteFX, NSCodec,
RemoteFX Image и JPEG; сохраняет 32-битные bitmap-обновления, обычное RDP-сжатие
и GDI orders. Сжатие bitmap может использоваться, но без цветовых потерь этих
графических кодеков. Этот режим не гарантирует FPS видео и может потребовать
больше полосы сети. Масштабирование текстуры GTK всё ещё может менять видимые
пиксели при несоответствии разрешения и области вывода. Авторазрешение через
DISP остаётся доступно. Проверять на реальном сервере по mode=classic и
classic_codec=bitmap; режим — способ сохранить точность и отделить влияние
графических кодеков от декодирования/вывода. Исчезновение полос на Windows
пока не подтверждено.
