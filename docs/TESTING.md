# Проверки

```bash
cargo fmt --check
cargo build --locked
cargo test --locked
cargo clippy --locked -- -D warnings
```

Обычные тесты не обращаются к пользовательскому Secret Service.
Интеграционная проверка сохранения, замены, поиска и удаления синтетического
пароля запускается отдельно:

```bash
sh scripts/test-secret-service.sh
```

Нужны `dbus-run-session` и `gnome-keyring-daemon`. Скрипт использует отдельную
D-Bus-сессию, временные XDG-каталоги и тестовое хранилище; личное хранилище
не используется. Сам ignore-тест отдельно в обычной сессии запускать не нужно.

В GUI проверить сохранение пароля, повторное открытие профиля и кнопку проверки
наличия, замену пароля, удаление пароля отметкой в форме. Пустое поле не меняет
существующий пароль. Изменение названия профиля не должно терять пароль.
При отказе или отмене системной разблокировки пароль не должен сохраняться
в SQLite или файлы; сообщение должно разделять сохранение параметров и пароля.
Повторное сохранение после ошибки не должно создавать второй профиль.
Удаление профиля сначала очищает локальный пароль; при ошибке очистки профиль
остаётся, чтобы можно было повторить операцию.

На KDE проверить Secret Service-провайдер отдельно. Пока не подтверждено
тестированием под KDE или Wayland. Матрица окружений находится в README.

## WebDAV

Обычные тесты проверяют URL, запрет открытого HTTP и встроенных в URL
учётных данных, ограничения формата и фильтрацию WebDAV XML.
Локальная интеграционная проверка транспорта:

```bash
cargo test --locked webdav_http -- --ignored
```

Использует только loopback и синтетические токены. Проверяет PROPFIND,
PUT с If-None-Match: *, GET, передачу зашифрованного тела, HTTP 401/412,
отказ следовать перенаправлению и слишком большой ответ. В тестовом fixture
HTTP разрешён явно; производственный конструктор разрешает только HTTPS.
Отдельный тест Secret Service проверяет, что токен WebDAV и пароль RDP
с одинаковым UUID находятся в разных пространствах и удаляются независимо.
Реальный Nextcloud и TLS-сертификат пользователя требуют ручной проверки.

## Общий сценарий GUI

- Меню «⋮» → «Импорт Remmina» → автоматический поиск и выбор каталога;
  проверить отметки, выбор всех и пропуск дубликатов.
- Меню «⋮» → «WebDAV / Nextcloud…»: ввести URL существующей папки,
  пользователя и пароль приложения; проверить список.
- Сохранить настройки/пароль, переоткрыть окно и проверить доступ при пустом
  поле токена через локальный Secret Service.
- Отметить часть подключений, задать/повторить мастер-пароль, отправить набор.
- Обновить список, открыть отправленный набор с просмотром; проверить
  пропуск совпадения, выбор конфликтов и отказ при неверном мастер-пароле.
- При изменении URL/пользователя старый токен не подставляется автоматически;
  после изменения URL список нужно обновить.

## SFTP

```bash
sh scripts/test-sftp.sh
```

Нужны OpenSSH server/client и python3. Скрипт под обычным пользователем
запускает отдельный sshd только на loopback и отдельный ssh-agent, генерирует
временные тестовые ключи, удаляет fixture после завершения. ~/.ssh и системная
конфигурация SSH не изменяются; личные ключи и пароли не используются.
Тест проверяет непризнанный ключ сервера, отклонение подмены, known_hosts
с портом, обычный/зашифрованный OpenSSH Ed25519-ключ, неверную passphrase,
SSH-agent, загрузку/отправку зашифрованного набора, права 0600, запрет
перезаписи, символических ссылок и слишком больших файлов.
Успешный вход по паролю пользователя не тестируется этим fixture: тестовый
сервер разрешает только сгенерированные публичные ключи. Его следует
проверить вручную на сервере с разрешённой парольной аутентификацией.

Обычный тест базы проверяет независимость локального доверия от профилей,
привязку к host/port и запрет замены уже сохранённого ключа. Изолированный
тест Secret Service проверяет раздельное хранение и удаление секретов
RDP, WebDAV и SFTP с одинаковым UUID.

В GUI одним проходом проверить выбор файла ключа, подтверждение отпечатка
нового сервера, обновление списка, отправку/открытие набора, сохранение
passphrase и повторный вход после переоткрытия окна, затем режим SSH-agent.
Не подтверждать изменённый ключ без отдельной проверки у администратора.
