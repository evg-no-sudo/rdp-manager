# WebDAV / Nextcloud

Реализован ручной обмен зашифрованными наборами. Это ещё не автоматическая
синхронизация: отправка не объединяет наборы, отсутствующие записи не удаляют
локальные профили. Каждый экспорт создаёт новый файл с временем UTC и UUID.

## Настройка

1. В Nextcloud создать отдельную папку, например `RdpManager`.
2. В настройках безопасности Nextcloud создать пароль приложения.
3. Открыть меню «⋮» → «WebDAV / Nextcloud…».
4. Указать HTTPS URL именно этого каталога, например:
   `https://cloud.example/remote.php/dav/files/USERNAME/RdpManager/`.
5. Ввести пользователя WebDAV и пароль приложения. Нажать проверку подключения.
6. При желании сохранить настройки и пароль на этом ПК. URL/пользователь/UUID
   попадут в `$XDG_CONFIG_HOME/rdp-manager/webdav.json` (по умолчанию
   `~/.config/rdp-manager/webdav.json`), пароль — только в Secret Service.

Поле пароля приложения при повторном открытии остаётся пустым. Для ранее
сохранённой пары URL/пользователь пароль будет прочитан из локального Secret
Service при операции. При изменении адреса или пользователя требуется новый
явно введённый пароль. Без сохранения можно работать с паролем, введённым
только в текущем окне. Недоступный Secret Service не приводит к сохранению
токена в открытом файле. Главный пароль учётной записи Nextcloud не требуется.

Документация Nextcloud:
[доступ через WebDAV](https://docs.nextcloud.com/server/stable/user_manual/en/files/access_webdav.html).

## Передача

Для отправки отметить подключения и ввести отдельный мастер-пароль набора
с подтверждением (минимум 12 символов). Затем нажать отправку.
На принимающем устройстве настроить тот же каталог, обновить список,
выбрать набор и ввести его мастер-пароль. После загрузки открывается общий
просмотр с выбором подключений и ручным разрешением отличий.

Мастер-пароль не сохраняется. Пароли RDP не входят ни в открытый JSON,
ни в зашифрованный набор. Пароль приложения WebDAV используется в HTTPS
Authorization для доступа к самому серверу, но не записывается в набор.
Формат шифрования и ограничения описаны в [TRANSFER.md](TRANSFER.md).

## Транспорт

- Только HTTPS с проверкой сертификатов через системные доверенные корни.
  Автоматического обхода TLS-ошибок нет. Самоподписанный сертификат должен
  быть корректно добавлен в системное доверие администратором.
- Перенаправления отключены; нужно указать конечный адрес каталога.
- `PROPFIND Depth: 1` запрашивает только типы ресурсов и время изменения.
  Принимаются только файлы `rdp-profiles-*.rdpm` непосредственно в выбранном
  каталоге того же origin; посторонние URL, пути, XML DTD и неизвестный формат
  отклоняются/игнорируются. Каталог ограничен 2000 наборами и 2 МиБ XML.
- `PUT If-None-Match: *` отправляет новый неизменяемый снимок. Существующий
  объект не заменяется. Папка не создаётся автоматически.
- `GET` ограничен 4 МиБ; расшифровка и проверка выполняются до применения к базе.
- Соединение ограничено 10 секундами, запрос — 45 секундами. Работа выполняется
  вне главного потока GTK. Ошибки авторизации, прав, квоты, блокировки,
  отсутствующего каталога и перенаправлений отображаются отдельно.
- Сырые ошибки reqwest, HTTP-тела ошибок и Authorization не выводятся в GUI
  или диагностический журнал.

Протокол проверен локальным тестовым сервером. Доступ к конкретному Nextcloud
пользователя не выполнялся; конечная совместимость проверяется в GUI.
