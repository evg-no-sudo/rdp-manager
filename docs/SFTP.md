# SFTP / SSH

Меню «⋮» → «SFTP / SSH…» — ручной обмен теми же зашифрованными `.rdpm`-наборами,
что используются для папки и WebDAV. Формат описан в [TRANSFER.md](TRANSFER.md).
Автоматическое слияние и перенос удалений ещё не реализованы.

## Подключение

Указать сервер (DNS, IPv4 или IPv6), отдельный порт, пользователя и существующий
каталог. Поддерживаются абсолютный путь и путь относительно домашнего каталога
SFTP. Например, `rdp-manager` или `/srv/rdp-manager`. `~` не разворачивается,
родительские компоненты `..` не принимаются. Каталог автоматически не создаётся.

Выбрать один способ входа:

- **SSH-agent:** приложение использует `SSH_AUTH_SOCK` текущей сессии;
  агент должен быть запущен и содержать подходящий ключ. Подпись выполняет
  агент. Предлагается до 16 ключей; SSH-сервер может ограничивать число попыток.
- **Файл SSH-ключа:** выбрать приватный ключ через системный файловый диалог.
  Для зашифрованного ключа ввести passphrase. Ключ остаётся в исходном файле;
  его содержимое не копируется в настройки или наборы. Проверены обычный
  и зашифрованный OpenSSH Ed25519-ключи. Другие форматы зависят от libssh2/OpenSSL.
- **Пароль SSH:** ввести пароль пользователя; сервер должен разрешать этот метод.
  Автоматического переключения на другой способ входа при отказе нет.

Пароль SSH или passphrase можно необязательно сохранить через Secret Service.
Настройки сохраняются кнопкой; без отметки пароль остаётся только в текущем окне.
При повторном открытии поле пустое, сохранённый секрет загружается при операции.
Он привязан к серверу, порту, пользователю, способу входа и пути ключа.
При смене этих параметров секрет от старого подключения не подставляется.
При смене способа входа введённое поле секрета очищается.

Несекретные настройки находятся в `$XDG_CONFIG_HOME/rdp-manager/sftp.json`
(обычно `~/.config/rdp-manager/sftp.json`). В файле есть путь к ключу,
но нет его содержимого, SSH-пароля или passphrase. В наборы профилей не входят
ни эти настройки, ни секреты. Мастер-пароль шифрования набора задаётся отдельно.

## Проверка сервера

Проверка ключа сервера выполняется до пользовательской аутентификации.
Приложение читает `~/.ssh/known_hosts` в формате OpenSSH, не изменяя его,
и собственные подтверждённые ключи в локальной SQLite-таблице
`trusted_sftp_hosts` (схема 3; профили сохраняются при обновлении).

Для нового сервера показываются host/port, тип ключа и SHA256 fingerprint.
После отдельного подтверждения отпечаток сохраняется локально; выбранную
операцию нужно повторить. Соединение при повторе проверяет ключ заново.
Сохранённое доверие не переносится на другие устройства вместе с профилями.

Если ключ отличается от `known_hosts` или локально подтверждённого,
авторизация останавливается. Автоматической замены доверенного ключа нет;
ротацию следует отдельно подтвердить у администратора и обновить доверие.
Ошибку чтения known_hosts приложение также не обходит молча.

## Обмен

Обновить список, выбрать нужные локальные подключения, задать и повторить
мастер-пароль набора, отправить. Для загрузки выбрать набор и ввести его
мастер-пароль; затем открывается общий просмотр новых/изменённых профилей.
Локальные пароли RDP при переносе не изменяются.

Отправка создаёт уникальный временный файл с правами 0600, записывает только
шифротекст и закрывает его. Затем выполняется SFTP rename без OVERWRITE
в имя с временем UTC и UUID. Ошибка публикации не заменяет существующий файл;
временный файл при ошибке по возможности удаляется. Если поддерживается
fsync OpenSSH, он выполняется до публикации. Незавершённые временные файлы
не показываются в списке наборов.

Список ограничен 2000 наборами и 20000 записями каталога; принимаются только
обычные файлы с именами `rdp-profiles-*.rdpm`. Символические ссылки не загружаются.
Размер набора ограничен 4 МиБ. Все операции SSH и шифрования идут в рабочем
потоке. TCP connect ограничен 10 секундами на адрес (до четырёх адресов),
тайм-аут SSH-операций — 30 секунд; DNS разрешается системным resolver.
Тексты ошибок библиотек с содержимым пользовательских путей/данных в UI
не выводятся. Приватный ключ не передаётся SSH-серверу: используется подпись.
