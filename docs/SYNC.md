# Синхронизация: согласованные требования

Статус: реализован ручной зашифрованный обмен через папку и WebDAV/Nextcloud
с выбором профилей и предпросмотром. Автоматическое слияние, перенос удалений,
прямые SMB и SFTP ещё не реализованы. См. [TRANSFER.md](TRANSFER.md) и [WEBDAV.md](WEBDAV.md).
Целевые хранилища: локальная папка, WebDAV/Nextcloud, SMB и SFTP.
Сторонняя программа синхронизации на устройствах не требуется.
Nextcloud пользователя — целевой сервер для проверки WebDAV.

## Общий механизм и выбор хранилища

В настройках пользователь выбирает один активный источник синхронизации:

| Хранилище | Настройка |
| --- | --- |
| Локальная папка | Выбор каталога на диске, внешнем носителе или уже подключённом сетевом ресурсе |
| WebDAV / Nextcloud | HTTPS URL каталога, пользователь, пароль приложения |
| SMB | Сервер, общий ресурс, каталог, пользователь/домен и способ аутентификации |
| SFTP | Сервер, порт, каталог, пользователь, SSH-ключ либо пароль |

Одна локальная папка на двух независимых ПК сама по себе не обеспечивает
связь между устройствами: нужен общий ресурс, переносимый носитель или
другой механизм доставки. Для прямого доступа к SMB/SFTP предусмотреть
встроенные адаптеры, без обязательного ручного монтирования ресурса.

Формат зашифрованных данных и механизм слияния общие; транспорт отвечает
за чтение, публикацию новой версии и обнаружение параллельной записи.
Не завязывать логику слияния на HTTP ETag и не переносить живую SQLite-базу.
При смене хранилища показывать содержимое нового источника до объединения;
отсутствующий или недоступный каталог не считать командой удалить профили.

Сначала реализовать локальную папку и WebDAV, затем SMB и SFTP.
Синхронизацию через локальную папку также использовать для проверки
формата, слияния и работы без сети.

Для SFTP обязательно предоставить выбор способа входа: SSH-agent,
файл SSH-ключа или пароль. Для файла ключа — системный диалог выбора;
для зашифрованного ключа — отдельный запрос passphrase с необязательным
сохранением в локальном Secret Service. Приватный ключ не копировать
в каталог приложения, наборы профилей или удалённое хранилище.

## Данные и защита

- Синхронизировать только явно перечисленные поля профиля: UUID, название,
  сервер, порт, пользователь, домен и поддерживаемые настройки подключения.
- Пароли RDP, пароли/токены хранилищ, SSH-ключи и локальные Kerberos-билеты никогда
  не включать в сетевой формат — даже внутрь зашифрованного пакета.
- Секреты хранить отдельно на каждом устройстве в Secret Service. После
  получения профиля на новом устройстве пароль вводится локально либо
  используется локальный Kerberos ticket cache.
- Содержимое файла профилей шифровать на клиенте с аутентификацией;
  мастер-пароль задаётся пользователем отдельно от пароля хранилища.
  Использовать готовую криптобиблиотеку, случайные соль/nonce и KDF для пароля.
  Проверять неверный пароль, повреждение и подмену до применения изменений.
- Для WebDAV подключение только по HTTPS с проверкой сертификата; ошибки TLS
  не обходить. Для Nextcloud предусмотреть отдельный app password.
- Для SFTP проверять SSH host key; при первом подключении показывать
  fingerprint для подтверждения, при изменении ключа останавливать доступ.
  Предпочитать SSH agent/путь к пользовательскому ключу; ключи не копировать
  в данные приложения. Пароль и passphrase при сохранении — в Secret Service.
- Для SMB предусмотреть аутентифицированный доступ с шифрованием SMB3;
  не включать SMB1, guest fallback или отключение проверки автоматически.
- В локальной папке тоже хранить только зашифрованный набор, без секретов.
- Формат обмена отделить от SQLite. Ввести версию формата, ограничения
  размера и явный allowlist полей; тестировать отсутствие секретов в payload.
- Для WebDAV защитить запись ETag/If-Match и If-None-Match при создании.
  Для папки/SMB/SFTP отдельно проверить гарантии блокировок и атомарности;
  одного временного файла с rename недостаточно для защиты от потери
  параллельных правок. Если нельзя гарантировать условную замену, использовать
  неизменяемые версии/операции с уникальными именами и последующее слияние.
  Не перезаписывать чужую версию без проверки; частично загруженные файлы
  не должны становиться опубликованными данными.
- До автоматизации сделать ручную кнопку синхронизации с просмотром
  добавлений, изменений, конфликтов и удалений. Не выбирать победителя
  конфликта по часам устройств: часы могут расходиться.
- Удаления передавать как отдельные записи (tombstones), чтобы старый
  компьютер не восстановил удалённые профили при следующем подключении.
- При сетевой ошибке, отмене или неверном мастер-пароле локальная база
  остаётся рабочей. Историю сессий по умолчанию не синхронизировать.

В приложении подготовлены стабильные UUID, независимое локальное хранилище
паролей и зашифрованный формат переноса. Добавлены настройки WebDAV и локальное
хранение пароля приложения отдельно от паролей RDP. Формат ручного снимка не содержит метаданных причинности
или tombstones; перед автоматической синхронизацией потребуется новая версия
формата. Снимки нельзя трактовать как полное состояние с удалениями.
