# Отдельный движок H.264

Системная FreeRDP 3.32.2 на машине разработки собрана без H.264/FFmpeg.
В проекте подготовлена отдельная FreeRDP той же версии с FFmpeg, SWScale
и экспериментальным аппаратным декодированием. Исходники закреплены на
commit 97eff6ddfbbfaa8e42a126d362686bd001ff8bdc официального репозитория.
Сборка и установка выполняются в .deps внутри проекта. Этот каталог и
дополнительные бинарники не включаются в Git.

## Сборка и запуск

На другой машине сначала установить зависимости сборки (для Mint/Ubuntu):

```bash
sudo apt install build-essential cmake git pkg-config libssl-dev libjson-c-dev libavcodec-dev libavformat-dev libavutil-dev libswscale-dev libswresample-dev
sh scripts/build-h264.sh
```

Запуск оптимизированной release-версии с отдельными библиотеками:

```bash
RDP_MANAGER_TRACE_GRAPHICS=1 sh scripts/run-h264.sh
```

На машине разработки библиотека уже собрана. Закрыть старые окна перед
запуском: GtkApplication может активировать уже работающий экземпляр.
Обычный cargo run продолжает использовать системную FreeRDP.
Скрипт запуска задаёт private PKG_CONFIG_PATH, LD_LIBRARY_PATH и отдельный
каталог Rust-сборки target/h264. Протоколы TLS/NLA и пространство доверия
сертификатов приложения сохраняются. Отключённые X11/Wayland-клиенты в
CMake относятся к отдельным исполняемым клиентам FreeRDP; наш UI использует GTK.

## AMD, Intel, NVIDIA и резервный режим

Автоматический выбор — предварительная эвристика по доступным render nodes,
а не доказательство работоспособности декодера. AMD/Intel запрашивают VA-API;
NVIDIA без доступного AMD/Intel — CUDA через FFmpeg. На гибридной системе
автоматически предпочитается доступный VA-API render node. Если устройства
недоступны, выбирается программное декодирование. Отказ создания аппаратного
контекста обрабатывает программный резервный путь FreeRDP.

Явные режимы:

```bash
RDP_MANAGER_H264_BACKEND=software sh scripts/run-h264.sh
RDP_MANAGER_H264_BACKEND=vaapi RDP_MANAGER_RENDER_DEVICE=/dev/dri/renderD129 sh scripts/run-h264.sh
RDP_MANAGER_H264_BACKEND=cuda sh scripts/run-h264.sh
```

Для CUDA нужны совместимые драйвер и FFmpeg. Наличие NVIDIA само по себе
не гарантирует ускорение. Конкретный CUDA device FreeRDP этой версии
не принимает через FREERDP_HWCTX_DEVICE; для нескольких NVIDIA требуется
отдельная проверка выбора устройства. Существующие FREERDP_HWCTX_TYPE и
FREERDP_HWCTX_DEVICE учитываются launcher при автоматическом режиме.

Native frontend разрешает аппаратный запрос только если загруженная
библиотека содержит H.264 и FFMPEG_HWACCEL. Флаг SoftwareGdi в этой версии
FreeRDP также управляет запросом аппаратного H.264. Наш framebuffer при этом
всё ещё проходит через CPU и GDK MemoryTexture. Zero-copy не реализован.

## Что проверено

- Сборка библиотеки и приложения; сетевые TLS/NLA, сертификаты, classic и EGFX.
- Синтетический H.264-кадр с проверкой декодированных пикселей на CPU.
- Программный резервный путь при заведомо отсутствующем VA-API устройстве.
- Создание VA-API контекста и декодирование синтетического кадра на AMD Radeon
  RX 9070 XT с Mesa/radeonsi. Это не тест игрового RDP-сеанса.
- Правила выбора AMD/Intel/NVIDIA/гибридной системы и отсутствующего устройства
  проверены на файловых fixtures. Реальные Intel и NVIDIA ещё не проверены.

```bash
sh scripts/test-h264-backend.sh
sh scripts/test-h264.sh
RDP_MANAGER_TEST_GPU=1 sh scripts/test-h264.sh
```

Для синтетического теста дополнительно нужен ffmpeg CLI с libx264.
Реальный сервер сам выбирает кодек: codec_id=9 означает Progressive,
11 — AVC420, 14/15 — AVC444. Даже с новой библиотекой сервер может выбрать
Progressive. hw_requested=1 и строка [rdp-decoder] означают запрос;
сообщение FreeRDP «Using ... for accelerated H264 decoding» и проверка
реальной нагрузки GPU нужны для подтверждения аппаратного пути сеанса.

Видео, задержка управления играми, звук, relative mouse, Intel/NVIDIA и
полная матрица Windows/xrdp и X11/Wayland остаются отдельными проверками.


Если важнее чёткость текста, выберите перед подключением графику
«Приоритет чёткости (без H.264)». Для динамичных сцен оставьте «Авто».
Кодек выбирается при соединении; для изменения режима нужно переподключиться.
