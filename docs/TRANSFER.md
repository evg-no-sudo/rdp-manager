# Зашифрованный перенос через папку

Первый работающий этап обмена профилями; автоматической синхронизации пока нет.

## Использование

1. Открыть меню «⋮» рядом с заголовком «Подключения» → «Обмен через папку…», отметить нужные профили.
2. Ввести и повторить отдельный мастер-пароль (минимум 12 символов).
3. «Сохранить выбранные в папку…» создаёт новый `rdp-profiles-<uuid>.rdpm`.
4. Передать файл на другой ПК или открыть его с общего/съёмного носителя.
5. В том же диалоге ввести мастер-пароль, нажать «Открыть зашифрованный набор…».
6. Просмотреть записи, отметить нужные и применить.

Профили с одинаковым UUID и полями пропускаются. При совпадении полей
с другим UUID запись также считается дубликатом. Изменённые профили
по умолчанию не отмечены; доступны сохранение копии с новым UUID
и замена локальной версии с сохранением UUID. Это ручное разрешение отличий,
без определения, на каком устройстве правка была сделана позже.

Если локальный профиль изменился после открытия просмотра, весь перенос
отменяется: нужно открыть файл заново. Все выбранные изменения записываются
одной SQLite-транзакцией. Локальные пароли не меняются и не удаляются.
При изменении сервера/пользователя сохранённый локальный пароль может больше
не подходить; это указано перед применением. Профили, отсутствующие в наборе,
не удаляются. Временная ошибка чтения каталога не означает удаление профилей.

## Формат v1

Бинарный заголовок: 8 байт `RDPMENC\x01`, 16 байт случайной соли,
24 байта случайного nonce. Далее — шифротекст JSON и 16-байтовый тег.

- Argon2id v19: 65536 КиБ памяти, 3 прохода, параллелизм 1, ключ 32 байта.
  Параметры фиксированы версией и не читаются из недоверенного файла.
- XChaCha20-Poly1305; весь заголовок используется как AAD.
- Для каждого экспорта системный CSPRNG создаёт новые соль и nonce.
- В JSON: версия и список профилей; поля только `uid`, `name`, `host`,
  `port`, `username`, `domain`. Локальный SQLite ID, пароли, токены,
  ключи и билеты не входят в тип переносимого профиля.
- Неизвестные поля и версии отклоняются. Ограничения: 4 МиБ файла,
  10000 профилей, 4096 байт на строковое поле, уникальные корректные UUID.
- Неверный пароль и повреждение дают общее сообщение; до успешной
  аутентификации файл не применяется к базе.

Набор шифруется в памяти. Временный файл содержит только шифротекст,
создаётся с правами 0600, синхронизируется и публикуется без замены
существующего пути. Файловая система должна поддерживать безопасную
публикацию `tempfile::persist_noclobber`; иначе операция завершится ошибкой.
Экспорт не перезаписывает общий файл, поэтому два устройства могут создавать
независимые снимки. Это не обеспечивает автоматическое слияние снимков.
Мастер-пароль и производный ключ не сохраняются в SQLite/настройках/наборе.
Потерянный мастер-пароль восстановить из файла нельзя.

Шифрование и файловые операции выполняются в рабочем потоке; выбор файла
и папки — через GTK FileDialog. Сейчас нужны локально доступные пути,
включая уже подключённые сетевые каталоги. Прямые WebDAV/SMB/SFTP — далее.

## Проверка

Автотесты проверяют обратное чтение, неверный пароль, повреждение соли,
nonce, шифротекста и тега, ограничения размера, allowlist полей,
права файла, публикацию без перезаписи, сохранение UUID, конфликт с правкой
после просмотра и откат транзакции при ошибке посреди набора.

В GUI проверить экспорт выбранного профиля, повторное открытие файла,
пропуск совпадения и ошибку неверного мастер-пароля. Затем изменить
локальный профиль, повторно открыть старый набор и проверить выбор
«Сохранить копию»/«Заменить локальный». На втором ПК импортировать профиль
и убедиться, что его пароль не появился в Secret Service.
